Privacy Policy

Questa informativa descrive come CORA Client Manager tratta i dati dell'utente, con particolare attenzione ai dati ottenuti tramite le API Google.

1. Identità e contatto

CORA Client Manager è un software desktop sviluppato e gestito da Andrea Zampirolo.

Contatto privacy e supporto: andrea.zampirolo.consulenze@gmail.com.

2. Principio local-first

CORA è progettato secondo un modello local-first: le informazioni operative principali dell'applicazione sono conservate sul dispositivo dell'utente e non vengono trasferite automaticamente a Google.

3. Dati Google a cui CORA può accedere

L'accesso a Google è opzionale e avviene solo dopo autorizzazione esplicita dell'utente tramite OAuth.

ServizioPermessoUso
Identità Googleopenid, emailIdentificare l'account Google collegato e mostrare all'utente quale account è connesso.
Google Drivedrive.fileCreare, caricare, scaricare o aggiornare file che l'utente gestisce tramite CORA. CORA non richiede accesso generale a tutti i file presenti nel Drive.
Google Calendarcalendar.eventsCreare, leggere e aggiornare gli eventi che l'utente sceglie di gestire o sincronizzare con CORA.

CORA non richiede permessi Gmail o Google Contacts.

4. Come vengono utilizzati i dati Google

I dati ottenuti tramite Google vengono utilizzati esclusivamente per fornire le funzionalità visibili richieste dall'utente: gestione di file tramite Drive, sincronizzazione degli eventi tramite Calendar e identificazione dell'account collegato.

I dati Google non vengono utilizzati per pubblicità, retargeting, profilazione pubblicitaria, vendita di dati, valutazioni creditizie o attività estranee alle funzionalità di CORA.

5. Conservazione

I dati operativi possono essere conservati localmente sul dispositivo dell'utente quando necessari al funzionamento di CORA, ad esempio identificativi di file o eventi, stato della sincronizzazione, hash tecnici e metadati di collegamento.

I token OAuth non vengono memorizzati in chiaro nel database operativo di CORA. Nella versione Windows sono conservati tramite il vault credenziali del profilo utente.

6. CORA Inbox

CORA può utilizzare una cartella locale scelta dall'utente come “CORA Inbox”. Se quella cartella viene sincronizzata tramite Google Drive per desktop, la sincronizzazione del filesystem è gestita dal software Google installato dall'utente. CORA osserva la cartella locale e non usa un accesso globale al Drive per scandagliare file arbitrari.

7. Condivisione e accesso umano

CORA non vende i dati Google e non li trasferisce a piattaforme pubblicitarie o data broker.

L'accesso umano ai dati dell'utente non avviene normalmente. Può verificarsi soltanto quando l'utente fornisce volontariamente file o informazioni all'assistenza, oppure quando necessario per sicurezza, prevenzione di abusi o obblighi di legge.

8. Disconnessione e revoca

L'utente può scollegare il proprio account Google da CORA. La disconnessione rimuove l'autorizzazione locale utilizzata dall'app, ma non elimina automaticamente i dati già presenti in CORA o gli elementi già presenti nei servizi Google.

L'utente può inoltre revocare l'accesso a CORA dalle impostazioni di sicurezza del proprio account Google.

9. Sicurezza

CORA applica separazione per profilo, minimizzazione dei permessi, gestione protetta delle credenziali e diagnostica progettata per non includere token o contenuti sensibili.

10. Uso dei dati Google

L'uso da parte di CORA delle informazioni ricevute dalle API Google è limitato alla fornitura e al miglioramento delle funzionalità rivolte all'utente descritte in questa informativa ed è progettato per rispettare i requisiti applicabili della Google API Services User Data Policy e di Limited Use.

11. Aggiornamenti

Questa informativa può essere aggiornata quando cambiano le funzionalità di CORA o le modalità di trattamento. La data di aggiornamento è indicata in alto.

12. Contatti

Per richieste relative alla privacy: andrea.zampirolo.consulenze@gmail.com.
